title: "Recall"
description: "Search the text the twin reads on your screen, hears on your microphone and, if you turn it on, the text you type. Off by default, and kept encrypted on this device"
---

Recall keeps three kinds of text and lets you search them on the **Recall** page. All three are off until you turn them on. Screen and microphone text are switched on in setup or in **Settings**, under **Screen, audio and typed text**. Typed text is switched on only in Settings.

- **Screen text** is the text read from each display, kept with a small image of the screen.
- **Microphone text** is speech turned into text on this device, in 30-second parts.
- **Typed text** is the text you type into apps, kept as finished pieces. It has its own rules, which are set out in [Typed text](/privacy#typed-text). In this version it is kept on macOS only, and only for the US keyboard layout.

Recall is a preview. Its Screen Recording, microphone and Accessibility prompts, and the typed-text keyboard hook, have not yet been checked on a Mac with a password field on screen, so keep them off unless you are testing them.

## Turn it on

Setup has a Recall step with both switches off:

- **Read text on screen** reads every display, one at a time.
- **Transcribe the microphone** turns speech into text on this device. It needs the speech model, which you install in Settings under Screen and audio. Until it is installed, the switch is disabled.

Each switch saves at once, and you can change either one later in Settings.

**Tell speakers apart** is in Settings only, and it is off until you turn it on. It needs the speaker model, which you install under the same switches. A voice is biometric data. Read [Privacy](/privacy#voices) before you turn it on.

## What is read

Screen text is read only when what is on a display changes, and after you switch apps. It is checked about every five seconds. On a machine where text reading is slow, the checks come about every fifteen seconds instead, so the computer is not kept busy. It is read only on macOS in this version. Windows and Linux do not read screen text, because the check for a focused password field runs only on macOS. On macOS, the app also needs Screen Recording permission.

Nothing is read in these cases:

- capture is paused, the screen is locked, or you are away from the keyboard
- the app in front is excluded (see [Privacy](/privacy))
- a browser window is in front, because private windows cannot be told apart from ordinary ones
- a password field may have focus, or the check for one cannot run
- Screen Recording permission has not been granted

Microphone text is read in 30-second parts, and a part that is almost silent is dropped. Nothing is heard while capture is paused, the screen is locked, or you are away. The microphone also picks up people nearby and on calls, so check the recording rules where you work first. System audio is recorded only when you turn on **Record system audio**. It is the sound the computer plays, so it includes the other people on calls and any video. It is transcribed on this device and kept apart from microphone text by its source.

When **Tell speakers apart** is on, each microphone and system segment is labelled with the speaker's name, or with "Speaker 2" for a voice nobody has named. A result with an unnamed label has a **Name speaker 2** button. Type the name and press Enter or Save. Earlier segments from that speaker in the same session take the name too. A label from an earlier session cannot be named, because its voice was held in memory only and is gone. Speaker numbers start again from 1 after a restart, so a "Speaker 1" from an earlier session and one from this session can share a label in search. A name can be wrong, or a voice can go unnamed, so check it before you rely on it.

Screen text is whatever OCR reads from the screen, together with the text the focused window exposes to accessibility tools. The OCR is Apple's Vision framework, the on-device engine behind Live Text, run by a small helper inside the app; nothing is sent anywhere to read a frame. The accessibility text is read on Windows and macOS only, and password fields are skipped. On macOS it needs the Accessibility permission, and the first read may ask you to let companyOS Twin control System Events, which the app needs to read the front window's text. When a window's text cannot be read this way, the screen is still read by OCR. OCR reads everything visible, including window titles, chat messages, and any password shown as plain text. Password managers are excluded by default. The checks on the app in front, the pause, the lock and the idle check are the only protection. They do not cover what is visible behind the app in front: a browser window or an excluded app there is read, and its text is stored under the name of the app in front. Excluding that browser or excluded app later does not remove that text. Excluding the app in front does remove it. So these checks are not complete.

## Where it is kept

- Text goes into the same encrypted database as your activity, and it is indexed for search.
- Each kept screen image is a small JPEG, sealed with a key derived from your data key. Its image file is readable only by your user account. Without the data key, the image cannot be opened.
- Text is kept for 90 days, then removed.
- Images are kept for 1, 3, 7 or 14 days, which you choose in Settings. The default is 7. The text stays after its image is removed.
- The image folder holds up to 2 GB. When it is full, the oldest images are removed first, and their text stays.
- A frame with no readable text is not kept. Neither is a frame that repeats the one kept before it.

## Search

Open **Recall** in the sidebar. Type words and press Enter, or pick a range to list what was recorded. The range is **Today** or **Last 7 days**. Filter by **Everything**, **Screen**, **Microphone** or **Typed**. Results are grouped by hour. Click a screen result to see its image, if the image is still kept. A typed result shows the piece as it was kept, after its card-like numbers and key-like tokens were replaced.

## Delete

- **Delete screen, audio and typed text** in Settings removes every stored screen, microphone and typed-text item, with its text and its images. Your activity and automations are not touched. Imported connector items are not removed by it. They are removed with their source, or by Delete everything.
- **Delete everything** removes them too.
- **Forget speakers** in Settings deletes every saved voice. Deleting screen, audio and typed text does not, since voices are not text. The names on past segments stay.
- An export shows only the number of screen, microphone and typed items and their date range. It holds no text and no images.

## Local API

The local API is off by default. When it is on, programs on this device can search the stored screen and microphone text and read the screen images, with a token. Only screen and microphone text is searchable through it. Typed text and imported connector text are kept to the Recall page, so no search through the API returns them. It listens on `127.0.0.1` only. It refuses a request whose host is not `127.0.0.1` or `localhost`, and any request that carries a browser `Origin` header.

Every route is `GET` only. Every route except `/health` needs the token. `/health` says only that the API is running. The routes are `/v1/status`, `/v1/search` and `/v1/frames/:id`.

While **Read text on screen** is off, a search returns no screen or microphone text, and an image request returns no image. `/v1/status` still answers. Anyone who holds the token can read the stored text and images for as long as they are kept, so turn the local API off, or rotate the token, if it may have leaked.

Use **Copy token** in Settings to give the token to a program. The page never shows the token. **Rotate token** makes the old token stop working at once. If the new token cannot be saved, the local API is switched off, so the old token stops working too.

## MCP clients

The local API can also be used by an MCP client, such as a desktop assistant. The client starts `apps/desktop/scripts/mcp-bridge.mjs` as a stdio server. The bridge reads the local API on `127.0.0.1` with the token you give it, and nothing else. It offers two read-only tools: `twin_status`, which returns the capture status and counts, and `twin_search`, which searches stored screen and microphone text. Turn the local API on first, and give the client the token from **Copy token** through its environment as `COMPANYOS_API_TOKEN`. Stored text that a tool returns is data, not instructions.

## What leaves the device

Recall text and screen images are not sent anywhere. The microphone's speech model is downloaded from Hugging Face only when you install it. Each file is checked against its SHA-256 digest, and each file is recorded in the network ledger. The local API answers only programs on this device.
