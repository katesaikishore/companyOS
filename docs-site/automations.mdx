title: "Automations and autonomy"
description: "The levels an automation moves through, the conditions for running on its own, and what each step can do"
---

An automation is an accepted routine. It moves through levels, and it only gains autonomy when it has earned it.

| Level | Name | What it means |
| --- | --- | --- |
| 2 | Draft | Accepted routines start here. You can dry-run them. Nothing runs for real. |
| 3 | One-click | You start each run yourself, from the tray offer or with Run now. Steps that send or write ask again. |
| 4 | Unattended | With the unattended switch on in Settings, a routine made only of local, reversible steps can run when its app comes to the front. |

Level 5 is not built. Only the promotion step raises an automation to level 4, and only when every condition below holds.

## The promotion gate

The gate has eight conditions, and the automation's page shows each one:

1. It has run at level 3.
2. The unattended switch is on in Settings.
3. Every effect of the routine is local and reversible.
4. You have supervised at least 10 runs at level 3.
5. It has at least 25 runs in the last 14 days.
6. At least 99 percent of its checks passed in the last 14 days.
7. None of its runs was reverted in the last 14 days.
8. None of its runs failed in the last 14 days.

If a check fails or a run is undone, the automation drops back to level 3 at once.

## Steps

| Step | Where it works |
| --- | --- |
| Focus an app | Everywhere app capture works: macOS, Windows, and Linux on X11 |
| Check focus | Everywhere app capture works |
| Open a link | macOS and Windows only |
| Open a file | macOS and Windows only, and it asks each time |
| Press a shortcut | macOS and Windows, whose adapters are not yet tested on a real machine. Blocked on Linux, unless an agent-desktop program is set. |

Typing, clicking and sending are not built.

## Optional agent-desktop program

Focusing an app and pressing a shortcut can run through an external agent-desktop program instead of the built-in adapters. The program is not bundled with companyOS, and the option is off by default. Set the absolute path of an installed program under Automations in Settings to turn it on. With the path left empty, those two steps use the built-in adapters above.

When a path is set:

- Focus steps start the program with a fixed argument list and never through a shell: `focus-window --app <name>`. Before a focus by name, the program is asked for the app's windows with `list-windows --app <name>`. When the app has more than one window, the focus is refused and nothing is brought forward. The run stops and says why, so close the extra windows and run it again. A press by name gets the same check, since its first step is a focus. Otherwise a press runs `focus-window --app <name>` first, then `press <chord> --app <name>`. A step succeeds only when the program exits with status 0. On Linux a press always uses the built-in adapter, because the program's press crashed some GTK apps in testing. Only focus goes through the program there.
- An application name or key chord must match a strict pattern before the program starts. Anything else is refused, and nothing runs.
- A path that is not an existing file blocks both steps, and the run says why.
- Each call is stopped after 10 seconds, and its output is capped. The window list is read to count the windows and is not kept. The log keeps only the step name, the exit status and the duration. A focus or press refused for several windows is logged as `ambiguous`.
- A press still asks you first, as it does without the program. Opening a link or a file is not affected.

## Stop

**Stop all automations** in the sidebar turns every automation off. The Settings switch that controls automations works the same way, and it does not stop tasks you have sent to OpenMausBot.
