## 1. Capture

The twin polls the operating system every few seconds and records the name of the app in front, its window class, and whether you are idle. It records nothing else about the app.

- **Pause** stops recording until you resume. Locking the screen pauses it too, and it resumes at unlock unless you paused it yourself.
- **Exclusions** tell the twin never to record an app. Excluding an app removes its recent events. Handoff records saved by an earlier version keep the app name until they are removed after 90 days, or until you delete everything.
- **Browser capture** is off by default. When it is on, Chrome and Edge report only the host and a short path shape of the active tab. Titles, query strings and fragments are dropped. Private windows are skipped, so no page address is recorded for them, but the browser's name is still recorded as the app in front. It works on macOS and Linux only.
- **Screen text and microphone text** are a separate feature, called Recall, and both are off by default. When you turn one on, the twin reads text from the screen or the microphone and keeps it for search. Read [Recall](/recall) for what is read, where it is kept and when it stops.

## 2. Segment and mine

Events are grouped into stretches of work, separated by idle time. Routines are repeated app sequences inside those stretches. The twin looks at the last 30 days, and a routine needs at least three occurrences on at least three different days before it is suggested.

Routine detection is rule-based. No model is consulted to decide what counts as a routine.

## 3. Name

Each routine gets a rule-based name. Once a chat model is installed, a background worker can name routines instead, and the rule-based name is the fallback. Names are kept in memory only. The naming path has been run with real model files only in plain Node on one Linux machine (see `docs/research/real-model-checks.md`), not yet in a packaged build.

Setup also offers an optional decision model (Laya, about 1.7 GB). When it is installed, it labels the kind of work of a routine that includes an app the catalogue does not know, such as Documents or Messages. The label is shown only when the model is at least 70% sure. Otherwise a rule-based label is used. It does not decide what counts as a routine, and the checks in the next step stay fixed rules.

## 4. Draft, check and run

- Accepting a suggestion creates a **draft** at level 2. Drafts can be dry-run, which shows what each step would do without touching anything.
- At level 3 you start each run, from the tray offer or with **Run now**.
- Every step is checked by a local policy before it runs. Steps that focus mail or chat, or open a link, file or shortcut, ask you first.
- At level 4, with the unattended switch on, a routine made only of local, reversible steps can run on its own when its app comes to the front. Anything else still asks you, or does not run.

See [Automations](/automations) for the levels and the promotion gate.

## What it does not do

Typing, clicking and sending are not built, and neither is level 5. Activity capture never reads keystrokes, page text or window titles. Recall is the one exception, and it is off until you turn it on. When it is on, it reads the text visible on the whole primary screen, which can include window titles and page text, so a browser or excluded-app window visible behind the app in front can be read too. It reads the microphone in parts. See [Recall](/recall).
